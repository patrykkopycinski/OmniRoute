- **test(adobe-firefly):** the unit suite no longer launches a real Google Chrome. `ensureAdobeFireflySession` warms the session through the browser whenever it has no valid user JWT (`adobeFireflySession.ts::shouldWarm`), which is true by construction for every mocked-`fetch` test — so `adobe-firefly.test.ts` spawned the system Chrome at `firefly.adobe.com` with `--remote-debugging-port`, off-screen at `-32000,-32000`. Measured cost: ~9s of CDP wait in a single test (11× the 818ms it takes without), a leaked ~2MB Chrome profile per run under the temp `DATA_DIR` (90 dirs / 158MB observed on one machine, because the exit hook's `rmSync` races Chrome's own child processes and loses), a resulting `ENOTEMPTY` hook failure in `8510-adobe-firefly-edits-route.test.ts`, and an EDR alert on developer machines for a browser opened with remote debugging enabled. `tests/_setup/isolateDataDir.ts` now defaults `ADOBE_FIREFLY_BROWSER_REFRESH=0`, alongside the existing system-trust and DNS-write host guards; `||=` keeps the opt-in available to tests that genuinely cover the browser path. Production defaults are unchanged. Verified by mutation: with the guard reverted the same 6 files spawn 2 Chrome processes, take 20.7s and fail 1 test; with it, 0 processes, 4.0s, 85/85 pass.
